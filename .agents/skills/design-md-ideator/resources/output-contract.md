# Strict DESIGN.md Output Contract

This skill intentionally emits a complete subset stricter than the base specification.

## Required document shape

```markdown
---
version: alpha
name: <design-system-name>
description: <optional-description>
colors:
  primary: "#000000"
typography:
  body-md:
    fontFamily: <font-family>
    fontSize: 16px
    fontWeight: 400
    lineHeight: 1.5
    letterSpacing: 0em
rounded:
  md: 8px
spacing:
  md: 16px
components:
  button-primary:
    backgroundColor: "{colors.primary}"
    textColor: "{colors.on-primary}"
    typography: "{typography.label-md}"
    rounded: "{rounded.md}"
    padding: 12px
---

# <Optional document title>

## Overview

<Brand personality, audience, emotional response, density, and high-level direction.>

## Colors

<Color rationale and semantic roles.>

## Typography

<Font strategy, pairing, hierarchy, casing, and role guidance.>

## Layout

<Layout model, spacing rhythm, containment, responsive behavior.>

## Elevation & Depth

<Hierarchy method and exact shadow or flat-layering rules.>

## Shapes

<Shape language and radius usage.>

## Components

<Atom-specific conventions and interaction-state rules.>

## Do's and Don'ts

- Do <observable rule>.
- Don't <observable anti-pattern>.
```

## Canonical requirements

- Frontmatter starts on line 1 and uses exact `---` delimiter lines.
- Two-space YAML indentation; no tabs, anchors, aliases, sequences, block scalars, or multi-document YAML.
- Required top-level keys: `name`, `colors`, `typography`, `rounded`, `spacing`, `components`.
- Optional metadata keys: `version`, `description`.
- `colors.primary` is mandatory.
- Every typography entry contains `fontFamily`, `fontSize`, `fontWeight`, and `lineHeight`; include `letterSpacing` in generated output for completeness.
- Dimensions use only `px`, `em`, or `rem`.
- Component references use exact `{path.to.token}` syntax.
- All references resolve. Component `typography` may reference a composite typography token.
- All eight canonical sections appear once and in order using exact H2 headings.
- Unknown extra H2 sections are not generated by default. The base spec allows consumers to preserve them.
- Prose never contradicts tokens.

## Value policy

- Quote CSS colors and token references.
- Quote strings containing YAML-significant characters.
- Use numeric values for `fontWeight` and unitless `lineHeight` when appropriate.
- Component values may be quoted literals, dimensions, or token references.
- Prefer semantic references over repeated literals.

## Generation quality gate

Before validation, manually check:

- [ ] The document can stand alone without conversation context.
- [ ] Every prose claim maps to a token or explicit usage rule.
- [ ] Every token has a plausible consumer.
- [ ] State variants are unambiguous.
- [ ] Do's and Don'ts are testable.
- [ ] No placeholders or unresolved alternatives remain.
